# 给 Codex 的修复指令

## 目标

在当前最新工程与现有未提交改动基础上完成以下修复：

- 更换错误的战斧牛排美术。
- 更换错误的小炒黄牛肉美术。
- 补齐青菜炒牛肉和青菜牛肉汤美术。
- 把测试大厅全物品柜从 20×20 向下扩为 20×40。

不要重写玩法、配方、数值、背包架构或正式关卡资源系统。

## 开始前

先读取当前最新的五份 `AI_Context` 文档，再检查：

- 当前 ItemType/ItemCatalog；
- 物品美术映射目录；
- 品质与装盘状态的美术选择逻辑；
- 测试大厅全物品柜的数据网格、自动填充逻辑与滚动容器；
- 当前 Git diff，保留用户已有修改。

## 美术修复

把本补丁 `assets/ready` 中 8 张 PNG 复制到工程统一的物品美术目录，并按
`ASSET_MAPPING.md` 接入。

### 战斧牛排

- 普通战斧牛排使用 `weapon_tomahawk_steak_normal.png`。
- 非完美品质的盘装战斧牛排也使用普通版，除非当前设计已经有其他正式规则。
- 只有盘装战斧牛排且 `quality == PERFECT` 时使用
  `weapon_tomahawk_steak_perfect.png`。
- 删除或取消注册旧的圆头煎锅/肉锤状战斧图片，不能让它继续作为回退图。
- 保持战斧牛排从上到下 `2、2、1` 的异形占格，不得因为新纹理改成矩形。

### 小炒黄牛肉

- 未装盘使用 `dish_stir_fry_beef_unplated.png`。
- 已装盘使用 `dish_stir_fry_beef_plated.png`。
- 品质变化不应把它映射为青菜炒牛肉、牛肉炒饭或其他相似料理。
- 芥末改造继续沿用当前玩法逻辑；本任务不新增芥末专用图。

### 青菜炒牛肉

- 未装盘与已装盘分别使用对应 PNG。
- 画面特征应为青菜叶、浅色菜梗与熟牛肉片，不能误用青菜牛肉炒饭。

### 青菜牛肉汤

- 未装盘与已装盘分别使用对应 PNG。
- 必须映射为汤类图片，不能误用青菜粥、菜泡饭或青菜炒牛肉。

所有 PNG 使用透明通道、最近邻显示、关闭过滤和 mipmap。测试柜、背包、快捷栏、手持物与
地面掉落物共用同一映射来源。

## 测试大厅全物品柜扩容

当前标题和数据容量是 20×20。改为：

- 宽度保持 20 格；
- 高度改为 40 格；
- 总容量变为 800 格；
- 只向下扩展，不增加横向宽度；
- 保持竖向滚动查看；
- 自动填充/取走后自动补充逻辑必须能使用第 21—40 行。

不要只改标题或 UI 最小尺寸。以下三处必须统一为 20×40：

1. 实际异形背包数据网格；
2. 自动排列与容量判断；
3. UI 网格行数、内容高度和滚动范围。

标题同步显示为 `20×40 测试目录（滚动查看·取走后自动补充）`。

如果测试目录的尺寸来自共享正式仓库配置，不要修改正式仓库默认值；为测试大厅提供独立配置或
覆盖参数，避免正式游戏资源平衡被测试工具影响。

## 验收

1. Godot 启动无脚本或资源错误。
2. 测试大厅标题显示 20×40，能够滚动到底部第 40 行。
3. 自动填充可以越过原第 20 行，取走物品后仍能正确补充。
4. 测试柜中四组料理不再显示纯色占位块或错误相似料理。
5. 普通与完美战斧图切换正确，旧圆头战斧不再出现。
6. 未装盘使用普通容器，已装盘使用青花瓷餐具。
7. 异形占格、拖放、旋转和物品碰撞不因换图改变。
8. 运行现有 smoke tests，并人工完整滚动检查测试柜。
9. 更新五份 `AI_Context` 文档，记录美术映射、20×40 测试柜和测试结果。
10. 最后报告修改文件、接入的 8 张素材、测试结果以及仍存在的缺图项目。
