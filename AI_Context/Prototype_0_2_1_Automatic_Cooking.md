## 本轮目标与旧模式废弃原因

Prototype 0.2 的炒制需要玩家站在炒锅旁持续按住交互，无法验证“战斗过程中持续做饭”和多任务切换。0.2.1 废弃该灶台操作模式：玩家主动开火后，锅具、灶火与锅内内容共同推进计时，玩家可以离开去取料、洗盘或战斗，并在辣椒投入、成菜取出和过热前返回。

切割、腌制、水池洗盘与粘锅清洗仍保留持续按住交互；本轮没有补做煎、煮、炸路线。

## 自动烹饪与灶火规则

- 炒锅工位保存 `burner_on`，E 在开火 / 关火间切换。
- 炒锅正确放回对应工位、灶火开启、锅内有可烹饪内容、有油且未粘锅时，`WokStation._process()` 自动推进当前离散阶段。
- 玩家不需要在交互范围内，移动、攻击和其他世界活动不会暂停锅具。
- 第一阶段完整结束后进入“短炒完成”；没有辣椒时停止在此离散状态等待投料。
- 加入辣椒后自动开始第二阶段；完整结束后得到“待摆盘小炒黄牛肉”。
- 成菜未取出且继续受热，会完整经过【焦糊】计时，再经过焦炭计时，最终变为焦炭。
- 料理从锅中取出后灶火保持原状态；空锅开火当前安全，不会粘锅或损坏。
- 未加油的牛肉在开火状态下仍立即触发焦炭与【粘锅】事故，既有搬锅、持续洗锅和放回工位闭环不变。

### 中断与离散回退

关火、从锅中取出食物、拿走炒锅或使锅具离开工位时：

- 当前未完成阶段进度归零；
- 食物保持上一个已经完成的离散状态；
- 第一阶段已经完成时不会倒退；
- 已加入辣椒、盐和已有失败标签不会退回、消失或重新生成；
- 锅具放回且重新开火后，从当前离散阶段起点重新计时。

进度反馈只表达当前阶段时间，不生成“熟了 37%”之类中间物品。

## 灶台占位反馈

Prototype 0.2.1 最初使用炒锅上方横向进度条、状态文字、颜色和闪烁。该显示层在 Prototype 0.3.2 已被炒锅上方的世界空间环形指示器替代；自动烹饪数据、离散阶段和中断规则没有改变。当前以颜色、符号、静态环或阶段进度区分未开火、空锅开火、第一 / 第二阶段、等待辣椒、成菜等待取出、即将焦糊、已经焦糊、焦炭和粘锅。所有反馈均为 Debug 占位，不是正式视觉或声音方案。

## 主动调味数据

`ItemData.failure_tags` 只保存烹饪失误；`ItemData.active_modifiers` 独立保存主动改造：

- `SALTED`（内部语义 `salted`）
- `MUSTARD`（内部语义 `mustard`）

物品占位与 Debug UI 分开显示品质、失败标签和主动调味。转换为待摆盘 / 已摆盘料理时，两类数据都会保留，但只有失败标签参与既有瑕疵 / 糟糕品质计算。

## 盐

- 可在牛肉下锅后、第一阶段期间、第一阶段完成后、加入辣椒后和第二阶段期间加入。
- 一旦形成待摆盘料理，不再允许加入。
- 成功加入消耗一份盐，当前计时不重置；之后关火或搬锅仍保留盐标记。
- 不改变料理名称、身份、直接伤害、攻击间隔、射程、宽度、击退和完美终结。
- 已摆盘料理最大耐久增加 `salt_durability_bonus`。

## 芥末与怪异料理

- 芥末只能在得到待摆盘小炒黄牛肉后、开始摆盘前通过 M 加入。
- 不允许下锅前、炒制中、开始摆盘后或攻击后加入。
- 芥末不算失败标签，可与盐同时存在。
- 含芥末料理属于怪异料理：无标签时即使 QTE 命中完美区也最高为正常；一个失败标签仍为瑕疵，两个及以上仍为糟糕；不触发大型暴怒公牛终结。
- 普通公牛直接伤害乘以较低倍率，命中敌方后附加毒伤；完整直接伤害加毒伤高于普通版本。

## 毒伤结构

`StatusEffectData` 保存持续伤害类型、单次伤害、间隔、持续时间、来源阵营和是否刷新；`DamageOverTimeController` 可挂在伤害接收对象上，负责统一计时与按间隔结算。普通公牛只负责在直接命中成功后转交效果副本，不包含小炒黄牛肉专用毒计时代码。

当前芥末毒效果重复施加时刷新持续时间；该规则与数值均为 Prototype 临时方案。

## 芥末瞄准副作用

只有当前格是芥末战斗料理且玩家持续攻击时启用：

1. 基础鼠标瞄准方向叠加正弦角度摆动，幅度和周期固定，可观察与预判，不逐帧随机。
2. 系统按固定间隔进行一次喷嚏概率检查。命中后先进入短预警，再施加一次随机正负的大角度偏移，短暂维持后快速恢复到当时的基础方向与规律摆动。
3. 喷嚏不额外消耗耐久；已经释放的公牛保存生成时方向，不跟随准心变化。
4. 松开攻击、切换物品、打开 UI 或料理耗尽后立即清除玩家干扰。
5. 一定半径内加入 `aim_influence_receiver` 组的远程友方测试单位接收同一摆动与喷嚏偏移接口；离开范围或效果结束时清零。

近战友方如何处理尚未确定，本轮没有设计。

## 盐与芥末共存及数值顺序

集中计算顺序位于 `PrototypeCombatConfig.apply_combat_dish_stats()`：

1. 按品质确定标准 / 瑕疵 / 糟糕的基础伤害和耐久；
2. 盐增加固定耐久；
3. 芥末乘算直接伤害并写入毒伤参数；
4. 最后判断完美终结资格，芥末怪异料理始终排除。

因此盐与芥末同时存在时，盐耐久、芥末直接伤害 / 毒伤 / 瞄准副作用均生效，但盐不能恢复完美品质或大型公牛终结资格。

## 操作按键（Prototype）

- WASD：移动
- 鼠标滚轮或数字键 1—5：切换 Prototype 0.3.2 五格快捷栏
- E：炒锅工位开 / 关火；其他工位持续加工或打开食材柜
- F：当前格物品与工位交互、向锅内投料、取出锅内料理
- R：拿起 / 放回炒锅
- M：向物品栏中的待摆盘小炒黄牛肉加入一份芥末
- Space：开始摆盘 / 确认 QTE
- 鼠标左键：按住使用已摆盘料理连续攻击
- Q：丢下当前格物品
- Esc：关闭食材柜

键位均为 Prototype 临时方案。

## 正式确认、临时方案与长期方向

### 已正式确认

- 灶台烹饪开火后自动推进，离开工位不暂停。
- 关火 / 取出 / 搬锅使当前未完成阶段归零，已完成状态和已投材料保留。
- 盐和芥末是主动调味改造，不是失败标签；两者可共存。
- 盐的加入窗口与耐久方向；芥末的摆盘前窗口、怪异料理品质限制、毒伤和瞄准副作用方向。
- 第一版不加入生抽。

### Prototype / Debug 临时方案

- 全部计时、伤害、耐久、倍率、毒伤、概率、角度、半径和键位。
- 空锅持续开火安全；没有燃气、火灾或设施损坏。
- 芥末毒刷新持续时间；远程友方使用静止假人验证接口。
- Debug 状态文字、世界空间环形阶段提示、闪烁与准心线。

### 长期扩展方向

未来可能存在专门使用怪异料理的角色，可让怪异料理获得完美品质，并以正常料理输出下降或正常料理制作时间延长作为可能代价。

### 尚未确定

- 上述怪异料理角色的身份、数值、具体代价与是否进入正式 Demo。
- 近战友方受到芥末影响时如何处理。
- “普通调料 / 危险调料”是否成为正式分类。
- 当前盐、芥末数值及毒伤刷新规则是否保留。
- 自动烹饪、喷嚏和友方影响的最终手感参数。

## 已知问题

- 自动化测试验证规则和状态转换，不代替编辑器内对多任务压力、灶台警告可读性、芥末喷嚏挫败感和毒伤节奏的人工判断。
- 自动烹饪反馈仍是占位色块、局部环形提示和闪烁；没有正式声音，扩大相机视野后的远距可读性仍需人工试玩。
- Debug 友方假人只验证瞄准影响接口，没有真实远程攻击，因此未验证完整联机或召唤物体验。
- 毒伤当前仅由测试假人接收；正式敌人出现后需要复用同一状态接口并补充正式反馈。
- 空锅开火没有代价是明确的 Prototype 简化，不能被视为最终厨房规则。

## 下一步建议

在 Godot 编辑器内手动同时进行自动炒制、取料、洗盘和攻击，记录玩家是否能预测回场时机；分别试玩普通、加盐、加芥末及盐芥末共存料理，重点判断芥末总收益是否值得承担品质上限与瞄准干扰。完成体验复盘前，不扩展新料理、新主食材、生抽或大型波次系统。

## Prototype 0.3.1 时间与反馈修订

实际试玩确认 1.3/1.4 秒的两段自动炒制过快，无法支撑离灶战斗与多任务切换。0.3.1 将第一阶段调整为 3.6 秒、第二阶段调整为 3.9 秒；成菜到【焦糊】由 1.5 秒调整为 2.7 秒，焦糊到焦炭调整为独立的 2.0 秒。加盐不重置进度、关火或搬锅使当前阶段归零、已加入辣椒与盐保留、成菜后继续受热才焦糊等规则全部不变。

Prototype 0.3.1 曾加入远距离 `CookingStatusUI`；Prototype 0.3.2 已按试玩反馈移除该屏幕固定普通烹饪提示，改用炒锅局部环形提示，并通过扩大相机视野改善观察范围。全局来袭、波次完成和玩家失败提示继续保留。最终图标、声音和无障碍表现仍未确定。
