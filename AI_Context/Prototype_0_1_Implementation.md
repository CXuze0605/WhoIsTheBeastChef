## 本次实际实现

Prototype 0.1 已实现一条可运行的厨房制作闭环：

```text
整块生牛肉
  → 第一次完整切割：生牛排
  → 第二次完整切割：生牛肉片
  → 加入腌肉料并完成腌制：腌牛肉片
  → 炒锅提前加油
  → 放入牛肉片并完成第一阶段短炒
  → 加入辣椒段
  → 完成第二阶段炒制
  → 待摆盘小炒黄牛肉
```

同时实现厨房事故闭环：

```text
未加油的炒锅放入牛肉并开始加热
  → 焦炭作为可拿取的 Debug 占位物出现在工位旁
  → 炒锅进入【粘锅】状态并停工
  → 玩家使用 R 拿起粘锅
  → 手持粘锅到水池按住 E 清洗
  → 洗净炒锅继续留在手中
  → 玩家使用 R 将炒锅放回原工位
  → 工位恢复可用
```

已实现的错误与品质路线：

- 未腌制牛肉片仍可成菜，添加内部标签 `unmarinated`，临时显示【未腌制·临时标签】。
- 第一阶段完成前加入辣椒仍可成菜，添加内部标签 `chili_too_early`，临时显示【辣椒过早·临时标签】。
- 一个失败标签为“瑕疵”，两个及以上为“糟糕”，零标签为“正常”。
- 成菜后继续加热会添加正式【焦糊】标签；再次完成长时间加热会变为焦炭。
- 本期不实现摆盘 QTE，因此不会产生“完美”品质。

## 场景入口与运行方式

- Godot 工程：`GodotProject/project.godot`
- 项目主场景：`res://Scenes/prototype_0_1/main.tscn`
- 玩家场景：`res://Scenes/prototype_0_1/player.tscn`

运行方式：

1. 使用 Godot 4.6.2 stable 打开 `GodotProject/project.godot`。
2. 按 F6 可运行当前打开的测试场景；按 F5 可从已配置的项目主场景启动。
3. 如需重置全部 Debug 库存、工位与掉落物，游戏运行时按 T。

## Prototype 操作按键

| 按键 | 临时操作 |
|---|---|
| WASD | 2D 俯视角移动 |
| E | 使用设施；切割、腌制和清洗持续按住；Prototype 0.2.1 在炒锅工位用于开 / 关火，炒制自动推进 |
| F | 拿起 / 放入普通物品；从工位取回内容物 |
| R | 从炒锅工位拿起炒锅，或将炒锅放回原工位 |
| Q | 将当前选中格的物品放到地面 |
| T | Debug 重置当前测试场景 |
| 鼠标滚轮 | 向上 / 向下循环切换三格快捷栏；柜子界面打开时禁用 |
| Space | Prototype 0.2：开始摆盘 / 在 QTE 中确认 |
| M | Prototype 0.2.1：向待摆盘小炒黄牛肉加入芥末 |
| 鼠标左键（按住） | Prototype 0.2：当前格为已摆盘小炒黄牛肉时连续攻击 |

这些按键尚未进行正式操作设计，也没有手柄、重映射或无障碍方案。

## 推荐手动验收步骤

Prototype 0.1.1 可同时携带三件物品。正确路线建议：

1. 靠近统一食材柜按 E，在界面中取出整块生牛肉、腌肉料和食用油。
2. 用滚轮选中牛肉，在切菜板按住 E 完成两次切割；再把牛肉片和腌肉料依次放进腌制区域。
3. 腌制完成后取回腌牛肉片；用滚轮选中食用油并用 F 加入炒锅。
4. 选中腌牛肉片放入炒锅，按 E 开火；第一阶段会自动短炒，玩家可以离开工位。
5. 通过统一食材柜取得辣椒段，第一阶段完成后选中并用 F 加入炒锅；第二阶段自动推进。
6. 空手靠近炒锅工位按 F，取出“待摆盘小炒黄牛肉”。

无油事故路线：

1. 不加油，直接把生牛肉片或腌牛肉片放入炒锅。
2. 按 E 开始加热，观察焦炭与【粘锅】状态。
3. 空手靠近工位按 R 拿起粘锅，到水池按住 E 直至完成。
4. 手持洗净炒锅回到原工位按 R 放回。

## Prototype 0.1.1：携带与取料体验优化

### 三格快捷栏数据结构

- `QuickInventory` 是独立于 UI 的 `RefCounted` 数据对象，内部用长度为 3 的数组保存 `CarryableItem` 节点实例，并记录 `selected_index`。
- 当前格物品挂到玩家 `HeldAnchor` 并显示；非当前格物品仍是同一节点实例，只是挂到 `InventoryStorage` 并隐藏。
- 物品的 `ItemData`、加工状态、失败标签、品质，以及 `WokItem` 的油、粘锅、锅内内容与原工位标识不会因切格重建或丢失。
- 每格最多一个实例，不堆叠。三格全满时，世界拾取和工位取出都会失败，物品留在原所有者处。

### 当前选中格与输入

- 当前格为空即视为没有手持物；工位放入、洗锅和丢弃只读取当前格。
- 鼠标滚轮向上选择上一格，向下选择下一格，并在 1 / 3 边界循环；每个按下事件只移动一格。
- 切格会取消正在进行的持续交互，保持“本阶段进度归零、已完成离散状态保留”的既有规则。
- 柜子界面打开时，滚轮、移动、场景交互、丢弃和锅具操作由玩家输入状态统一屏蔽。

### 拾取、取出、放入与丢弃

- 收纳优先当前空格；当前格有物品时使用编号最小的空格；成功后不强制切换当前格。
- 工位在确认有空格后才移交物品；满栏时不会先清空切菜板、腌制区或炒锅内容。
- 放入工位只消耗当前格，其他两格不变；工位拒绝物品时实例留在原格。
- Q 只把当前格实例放到玩家朝向附近并清空该格。
- 炒锅可进入三格快捷栏。此规则只服务 Prototype；大型锅具未来是否使用普通物品栏仍未讨论。

### 统一食材柜与 UI

- 测试场景只实例化 `Kitchen/IngredientCabinet`，旧的四个独立 `IngredientDispenser` 节点已移除；旧脚本保留但未被场景使用。
- 柜中包含整块生牛肉、腌肉料、辣椒段和食用油。库存配置位于 `main.tscn` 的 `IngredientCabinet` 导出属性，当前各为 12 份 Debug 数值。
- 玩家靠近按 E 打开；Prototype 0.2.1 界面显示牛肉、腌料、辣椒、油、盐、芥末六种库存、各自“取出”按钮、玩家三格状态和关闭按钮。
- 只有库存大于零且玩家有空格时才创建并收纳物品，成功后库存减一；满栏不扣库存，零库存按钮禁用。
- 点击关闭、按 E、按 Esc 或离柜距离超过玩家交互距离会关闭界面。打开柜子的同一帧交互事件有明确帧保护，不会立即关闭。
- 界面显示鼠标且拦截鼠标输入；场景树保持运行，不使用 `paused`，以保留实时烹饪方向。

## Prototype 0.2：料理战斗闭环

Prototype 0.2 已在同一主场景中接入盘子真实物品、主动摆盘 QTE、小炒黄牛肉连续攻击、普通 / 大型公牛、阵营伤害、耐久耗尽变脏盘及水池连续洗盘。详细的数据结构、临时参数、验收覆盖和已知问题见 `AI_Context/Prototype_0_2_Combat_Dish.md`。

本轮仍复用三格物品实例所有权，不复制料理或锅具数据。盘子堆叠只对干净 / 脏盘开放；摆盘将盘子消耗一个单位并把原待摆盘料理实例原地转换为成品；料理耗尽再把同一实例原地转换为一个脏盘，因此切格不会重置品质、标签、伤害或耐久。

已使用 Godot 4.6.2 stable 通过 `prototype_0_2_smoke_test.gd` 七组 0.2 自动验收，并再次通过 `prototype_0_1_smoke_test.gd` 全量回归及主场景无界面启动检查。

## 已知问题

- 自动化测试已通过，但操作手感、路线距离和“忙而不繁琐”仍必须由开发者在编辑器中手动试玩判断。
- 三格比单件手持减少了无意义落地，但容量是否产生合适取舍仍需人工试玩；不能据此直接确定正式背包容量。
- 掉落物没有正式摆放、堆叠或防重叠规则，重复测试时可使用 T 重置。
- Debug UI 针对 1280 × 720，尚未验证其他窗口比例。
- 设施目前用可穿越的灰盒节点表示，只有厨房外边界参与碰撞；设施碰撞和正式空间布局尚未设计。
