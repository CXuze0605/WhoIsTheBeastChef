## 路线原则

- 先完成短而完整的纵向切片，再扩充料理和敌人内容。
- 每个里程碑都必须产生可运行版本。
- 新系统先用占位素材验证，不等待正式美术。
- 里程碑未通过退出条件时，不并行开启下一个主要系统。
- 优先保证核心闭环、稳定性和作品集可解释性。

阶段一实施说明：Prototype 0.1 第一期把 M1、M2 与 M3 的料理制作部分组合成厨房纵向切片，0.1.1 用三格快捷栏与统一食材柜优化携带和取料，0.3.2 再把临时容量调整为五格；0.2 跑通“制作 → 摆盘 → 料理攻击 → 耐久耗尽 → 脏盘清洗”的首个战斗闭环，0.2.1 再用离灶自动烹饪与盐 / 芥末改造验证多任务时间压力和同一道料理的构筑分支。小炒黄牛肉的公牛冲锋、数值和调味效果仍是首轮 Prototype 实验，不代表全部料理的最终架构。

Prototype 0.3 把 M4 的首个真实威胁和 M5 的最小波次骨架合并为同场验证：有限准备 → 双层预警 → 分批近战味真族 → 战斗与自动烹饪并行 → 全部复味或玩家失败。它不包含正式奖励、第二敌人或正式单局结构。

Prototype 0.4 已继续把 M4—M6 的技术骨架组合为自由准备、三种料理战斗形式、普通 / 重型两类敌人和三波连续测试。该组合只用于快速比较玩法，不代表 M4—M6 的人工验证和作品集完成度已经达标。

- 全局来袭预警、八个边缘候选点的合法性检查、局部方向预警和三批短间隔生成
- 所有计划敌人完成生成和复味离场后才结束波次；库存、盘子、锅具与灶火不重置
- 战斗、预警和波次结束均不暂停自动烹饪

明确未包含：第二敌人、远程 / 精英 / Boss、设施受伤、食材掉落、经验、正式 Roguelite 奖励、正式提前营业奖励、正式复味人形演出、正式死亡流程与多人。

## 缓冲与删减顺序

如果进度落后，按以下顺序删减：

1. 第三种料理或额外敌人类型。
2. 非关键动画和表现变体。
3. 次要 UI 与便利功能。
4. 复杂配方分支和随机成长。

不得优先删减：

- 收集、烹饪、战斗三者的因果关系。
- 完整胜负流程。
- 核心反馈与稳定性。

## Demo 之后

完成作品集 Demo 并复盘后，再决定是否进行：

- 多人混乱合作原型（包括本地多人等可能形式）
- 更多料理组合
- 轻量构筑或局外变化
- Game Jam 限时开发训练

这些方向目前不进入首版排期。
