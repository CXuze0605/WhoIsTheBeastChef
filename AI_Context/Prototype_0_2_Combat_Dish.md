## 本轮实际实现

Prototype 0.2 在原有小炒黄牛肉制作路线后接入以下闭环：

```text
待摆盘小炒黄牛肉 + 干净盘子
  → 主动开始横向摆盘 QTE
  → 已摆盘小炒黄牛肉（正常 / 完美 / 瑕疵 / 糟糕）
  → 按住攻击键持续释放料理能力
  → 每次成功释放消耗 1 耐久
  → 耐久耗尽
  → 原快捷栏格的料理实例转为 1 个脏盘子
  → 投入水池并持续清洗
  → 干净盘子堆的洗净回收统计增加
```

完美品质最后一份耐久使用独立终结路线：

```text
最后 1 耐久
  → 不释放普通公牛
  → 仅释放 1 头大型暴怒公牛
  → 撞边界反弹、间隔概率预警转向、敌我伤害
  → 持续时间结束后消失
  → 料理格立即转为脏盘子
```

原有三格栏、统一食材柜、切割、腌制、两阶段炒制、失败标签、品质、焦糊 / 焦炭、无油粘锅、手持洗锅和放回工位没有改写其既有规则。

## 操作按键

| 按键 | Prototype 操作 |
|---|---|
| WASD | 移动 |
| E | 使用设施或持续加工；在水池持续洗锅 / 洗盘 |
| F | 拿取、放入普通物品；从干净盘子堆领取 1 个盘子；把脏盘投入水池 |
| R | 拿起或放回炒锅 |
| 鼠标滚轮 | 循环切换三格快捷栏 |
| Space | 有待摆盘料理与干净盘时开始摆盘；QTE 中再次按下确认 |
| 鼠标左键（按住） | 当前格为已摆盘小炒黄牛肉时连续攻击 |
| Q | 丢弃当前格物品 |
| T | Debug 重置主场景 |

食材柜或摆盘 QTE 打开时会锁定移动、攻击、切格、丢弃与场景交互，但不暂停场景树。打开摆盘的同一帧不能立即确认，避免 Space 输入穿透。

## 盘子物品与堆叠

`ItemData` 新增干净盘子、脏盘子和已摆盘小炒黄牛肉类型，并保存：

- `is_stackable`
- `stack_count`
- `max_stack_count`
- `PlateState`
- `can_be_plated`
- `is_combat_dish`
- 战斗伤害、耐久和完美终结字段

干净与脏盘的 `max_stack_count` 为 4；其他当前物品仍不可堆叠。`QuickInventory` 会先检查整个 incoming stack 是否有足够容量，再按“当前兼容堆叠 → 其他兼容堆叠 → 当前空格 → 其他空格”的顺序收纳。容量不足时不修改来源物品，避免部分合并后丢失、复制或覆盖。

盘子可按单单位消耗：摆盘只从一个干净盘堆中减 1；堆叠减到 0 才移除节点。料理耗尽时不会直接删除实例，而是把原格中的同一个 `CarryableItem` 转为 `DIRTY_PLATE`，数量固定为 1。

## 干净盘子堆

水池旁的 `CleanPlatePile` 使用文字与色块占位。每次按 F 创建并收纳 1 个真实干净盘子实例；有兼容堆叠时合并，否则寻找空格，无法容纳时提示“物品栏已满”。

当前领取为无限供应，这是本轮已明确的 Prototype 领取方式。水池洗净盘子会增加盘子堆的“洗净累计”统计，但无限供应不会因领取减少；这不代表正式 Demo 的盘子资源来源已经确定。

## 待摆盘料理与主动摆盘

炒锅仍产出 `UNPLATED_STIR_FRY_BEEF`。该数据设置 `can_be_plated = true`，保留制作中的失败标签和品质基础数据，且 `is_combat_dish = false`，所以不能攻击，也没有允许继续切割、加热或调味的工位类型。

按 Space 开始摆盘时必须满足：

- 三格中存在待摆盘小炒黄牛肉；
- 三格中存在至少 1 个干净盘子；
- 食材柜等模态界面未打开；
- 玩家没有正在进行的持续交互。

系统锁定待摆盘料理所在格，立即消耗一个干净盘子，并进入 QTE。QTE 结束后把锁定的同一料理实例原地转换为已摆盘小炒黄牛肉，盘子与料理不再各占一格。流程中不允许切格或把料理交给其他工位。

## 摆盘 QTE 与品质转换

QTE 使用横向轨道、移动指针和绿色完美区域。指针往返移动；再次按 Space 时读取指针位置。

当前品质规则：

| 失败标签 | QTE 结果 | 最终品质 |
|---:|---|---|
| 0 | 未命中完美区 | 正常 |
| 0 | 命中完美区 | 完美 |
| 1 | 任意位置 | 瑕疵 |
| 2 个及以上 | 任意位置 | 糟糕 |

失败标签不会被 QTE 清除，也不会新增摆盘失败标签。失败料理命中完美区时没有品质补偿；这只是 Prototype 临时处理。正式设计中优秀摆盘是否给予其他补偿、普通完成是否只失去完美机会，仍保持未决。

## 最终小炒黄牛肉数据

已摆盘料理继续使用同一个 `ItemData` 保存：

- 料理类型与显示名称；
- 失败标签与最终品质；
- 当前 / 最大耐久；
- 基础 / 实际伤害；
- 是否具有完美终结效果；
- 承载盘子状态 `CLEAN`。

切换快捷栏只更换当前显示和交互引用，不重建实例，因此品质、标签、耐久和伤害保持不变。

## 品质与战斗属性

| 品质 | 伤害 | 最大耐久 | 大型公牛终结 |
|---|---|---|---|
| 完美 | 标准 | 标准 | 有 |
| 正常 | 标准 | 标准 | 无 |
| 瑕疵 | 标准 | 降低 | 无 |
| 糟糕 | 降低 | 降低 | 无 |

第三个及更多失败标签仅保留记录，不继续叠加战斗惩罚。品质不改变攻击距离、宽度、间隔、公牛速度、穿透或击退。

## 普通愤怒公牛

`DishAttackController` 只读取当前格中 `is_combat_dish` 的实例。按住鼠标左键时按集中配置的间隔释放；每次成功释放后才扣 1 耐久。松开、切格、打开 UI / QTE 或耐久归零都会停止继续释放。

`NormalBull` 是独立移动攻击实体：

- 从玩家面前沿鼠标瞄准方向生成；
- 使用宽条形检测区域向前移动固定距离；
- 可以穿透多个敌方目标；
- 用目标实例 ID 记录已命中对象，同一头公牛对同一目标只伤害一次；
- 造成轻微击退；
- 不伤玩家、友方或厨房设施；
- 离开测试范围或达到距离后消失。

普通公牛遇墙直接消失是 Prototype 临时处理。

## 大型暴怒公牛

`RagingBull` 使用独立脚本，不是只把普通公牛视觉放大。它具有更大的显示和命中半径、更高伤害、独立持续时间、反弹、随机转向预警、友伤和单目标命中冷却。

- 完美料理最后 1 耐久只生成 1 头大型公牛，不生成最后一头普通公牛；
- 遇测试场地边界时分别反射 X / Y 方向并把位置夹回合法范围，防止留在墙内；
- 转向概率只按固定间隔检查，不逐帧抽取；命中后先显示短暂“转向预警”，预警结束再换方向；
- 每个目标有独立命中冷却，允许以后再次经过时重新受伤，但避免连续物理帧扣血；
- 持续时间结束自动消失。

## 阵营、友伤与击退

`CombatRules` 定义 `PLAYER`、`ENEMY`、`FRIENDLY` 三种阵营，并由伤害接收对象报告自身阵营。普通公牛调用不启用友伤，只能伤害敌方；大型公牛显式启用友伤，可伤害玩家、敌方和友方测试单位。

厨房设施不加入 `damageable` 组，因此两类公牛都不能伤害食材柜、加工工位、炒锅、水池或墙体。玩家和 Debug 假人均实现统一的伤害参数入口、生命和衰减击退；玩家生命归零后仅执行原地 Debug 重置，不代表正式死亡流程。

## 脏盘池与连续清洗

玩家选中脏盘与水池按 F，会把当前整叠脏盘移出物品栏并加入水池的独立整数池。脏盘池与炒锅状态完全分开，不保存锅具，也不占快捷栏。

没有手持粘锅时，在水池按住 E 开始连续洗盘。会话开始时按脏盘数量锁定档位和每盘时间：

| 开始数量 | 档位 |
|---:|---|
| 1 | 基础速度 |
| 2–4 | 轻微加速 |
| 5–8 | 明显加速 |
| 9+ | 最高速度 |

持续按住时，洗完一个会增加干净盘子堆的洗净累计并自动洗下一个，速度不会因剩余数量减少而改变。松开后仅当前盘的进度归零，已经完成的盘子不倒退；下次按新的数量重新锁档。

手持粘锅时水池始终优先洗锅。炒锅继续使用固定粘锅清洗时间，不参与脏盘池、不堆叠、不接受洗盘速度加成，完成后仍在当前快捷栏格中并须亲自带回原工位。

## 正式确认与 Prototype 临时方案

### 已正式确认并按现有设计实现

- 摆盘由玩家主动开始；开始后料理彻底定型。
- 摆盘消耗一个干净盘子，盘子与料理合并为一个成品。
- 干净 / 脏盘每 4 个堆叠一格。
- 料理消耗后留下脏盘。
- 脏盘进入独立水池池，持续按住清洗，松开当前进度归零，已洗盘不倒退。
- 洗盘速度按会话开始数量分档锁定；持续按住自动洗下一个。
- 手持粘锅时优先洗锅，且洗盘加速不作用于炒锅。
- 失败标签不会被摆盘清除。

### Prototype / Debug 临时方案

- 三格栏承载盘子与炒锅、干净盘无限领取、Space / 左键操作。
- QTE 轨道、速度、完美区和失败料理无补偿规则。
- 小炒黄牛肉的公牛冲锋形态及全部战斗、耐久、概率、清洗数值。
- 普通公牛撞墙消失、固定矩形边界、纯色文字占位。
- 静止测试假人、简单生命、击退与玩家归零重置。
- 厨房设施通过不加入伤害组实现免伤；未实现正式碰撞层命名与复杂阵营关系。

## 明确未实现

- 新料理、新食材与其他料理战斗形态。
- 正式敌人 AI、敌人生态、生成、波次、胜负和肉鸽成长。
- 正式背包、物品体积、拖拽、普通食材堆叠与容量升级。
- 摆盘失败标签、失败料理的正式 QTE 补偿规则。
- 厨房设施破坏、食材打翻、墙体损坏或其他物理连锁事故。
- 正式关卡、美术、动画、音效、教程、手柄、键位重映射和联机。

## 已知问题

- 自动化验证覆盖状态和规则，但攻击手感、QTE 可读性、风险是否欢乐、三格压力和洗盘节奏仍需开发者亲自在 Godot 编辑器中判断。
- Debug UI 固定为 1280 × 720，信息较密，其他窗口比例可能出现拥挤；这不是正式 HUD。
- 普通 / 大型公牛使用轻量距离检测和固定测试边界，不是最终物理碰撞或导航实现。
- Debug 假人没有 AI，不会主动威胁玩家，因此本轮只证明“料理能造成战斗影响”，尚未完整证明“烹饪驱动胜负”。
- 干净盘子无限领取使洗净回收只提供流程验证和统计反馈，尚未形成正式资源压力。
- 随机转向的体验需要人工多次试玩；自动测试使用可控预警入口验证状态转换，不评估随机分布手感。

## 下一步建议

1. 手动跑通正常、完美、瑕疵和糟糕四条路线，观察攻击与品质差异是否能被直接感知。
2. 重点记录完美大型公牛的自伤 / 友伤是否带来可理解的欢乐事故，还是只造成挫败。
3. 观察从食材柜、三格携带、摆盘到洗盘是否形成节奏选择，删去无意义重复劳动。
4. 只修复阻断与可读性后再决定是否进入具有实际威胁的最小敌人实验；不要直接扩展新料理或大型波次系统。
