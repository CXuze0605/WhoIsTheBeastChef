# Coding Standards

> 最后更新：2026-07-19  
> 用途：规范未来 Godot 开发中的代码风格和工程习惯。

## 技术规范

- 使用 Godot 4.x。
- 使用 GDScript。
- 代码命名保持清晰易懂。
- 变量、函数、文件名优先使用英文。
- 文件名、变量和函数优先使用 `snake_case`，Godot 节点名使用清晰的 `PascalCase`。

## 代码结构原则

- 一个脚本负责一个主要职责。
- 避免单个脚本过度膨胀。
- 优先使用组合，而不是复杂继承。
- 避免为了未来可能需求提前设计复杂架构。
- 只有真实需求已经出现时，才提取公共模块或增加抽象层。

## 可维护性原则

- 重要逻辑添加必要注释，优先解释设计原因和非显然约束。
- 保持代码容易理解和修改。
- 优先选择当前阶段最简单可靠的实现方式。
- 修改后清理失效代码、未使用变量和无法解释的临时逻辑。

## AI 协作要求

AI 生成代码时：

- 解释关键逻辑。
- 说明代码放置位置以及关联的场景或节点。
- 避免引入当前项目不需要的复杂系统。
- 明确说明验证方式；无法实际测试时，说明尚未验证的部分。
