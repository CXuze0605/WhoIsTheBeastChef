# Prototype 0.3：基础味真族与首轮战斗循环

> **0.4 增量说明（2026-07-21）**：基础味真族追击、挥击、复味、导航和分批生成继续有效；首轮倒计时准备与单波结束流程已扩展为无倒计时 `FREE_PREPARATION`、两次 `INTERMISSION` 和三波连续测试。第二种重型味真族只通过高生命、韧性与击退 / 僵直抗性形成差异，当前不存在料理减伤或免疫。完整现行规则见 `Prototype_0_4_Beef_Branches_and_Multiwave.md`。

> 实现日期：2026-07-20  
> 场景入口：`res://Scenes/prototype_0_1/main.tscn`  
> 引擎验证：Godot 4.6.2 stable / Compatibility  
> 用途：灰盒玩法验证，不代表正式平衡、正式关卡、正式 UI 或美术

## 一、本轮实际实现

本轮首次跑通：

```text
有限准备
→ 倒计时结束或提前营业
→ 全局来袭预警
→ 地图边缘局部方向预警
→ 三个小批次进入
→ 玩家战斗与自动烹饪并行
→ 所有基础味真族完成复味并离场
→ 波次完成
```

玩家生命归零时进入 Prototype 失败状态。波次完成或失败都不会替玩家重置锅具、灶火、物品栏或库存；按 T 可快速重载整个测试场景。

## 二、已正式确认的设计

- 第一种味真族是缓慢逼近的近战追击者，只把玩家作为主要目标，不攻击设施、食材、盘子或料理。
- 攻击具有清晰前摇；挥击方向锁定后不继续追踪，玩家可以移动躲开；攻击后有后摇，再恢复追击。
- 味真族生命归零称为“完成复味”，不是正式世界观中的“死亡”。
- 准备和战斗处于同一连续场地；战斗、预警与波次完成都不能暂停自动烹饪。
- 准备和战斗共用同一份有限库存；进入战斗不补货、不返还资源。
- 全部计划批次完成生成且所有味真族完成复味离场后，波次才结束。
- 厨房设施没有生命，不是敌人攻击目标，也不受公牛或味真族伤害。

## 三、基础味真族状态机

`BasicTasteEnemy.State`：

```text
CHASE 追击
→ WINDUP 前摇并锁定方向
→ ATTACK 单次挥击判定
→ RECOVERY 后摇
→ CHASE
```

任意可受击战斗状态可进入：

- `HIT_STUN`：普通公牛或大型公牛直接命中后的极短反馈僵直；结束后回到追击。
- `REFLAVORING`：生命归零后停止危险行为、禁用碰撞、缩小淡出；结束时只通知 WaveManager 一次。
- `DISABLED`：玩家失败后停用剩余味真族，避免失败画面继续伤害。

攻击前摇开始时保存方向。攻击生效帧只做一次前方矩形范围检查，同一挥击不会逐物理帧重复扣血。Prototype 的玩家短暂受击保护也会防止同一次或重叠挥击造成连续扣血，但正式无敌帧规则尚未确定。

## 四、受击、击退与持续伤害

- 基础味真族实现现有 `damageable`、阵营、直接伤害和状态效果接口。
- 普通公牛可穿透并分别命中多只味真族；每头公牛对同一目标仍只命中一次。
- 直接命中会叠加击退速度并进入短僵直；僵直只用于命中反馈。
- 芥末毒伤继续由通用 `StatusEffectData` 和 `DamageOverTimeController` 结算，可以完成复味。
- 大型暴怒公牛继续使用友伤规则，可伤玩家、味真族和友方测试单位，不伤厨房设施。
- 玩家拥有生命、受伤闪色、轻击退和失败信号；不再在生命归零时静默满血复位。

## 五、碰撞与寻路

### 实体碰撞

- `World`：边界和六类厨房设施。
- `Player`：玩家实体。
- `Enemy`：基础味真族实体。
- 玩家碰撞体与 36 × 36 灰盒视觉接近。
- 味真族使用半径 14 的实体圆形碰撞，略小于约 50 × 58 的占位视觉。

统一食材柜、切菜板、腌制区、炒锅工位、干净盘子堆和水池均增加贴近占位矩形的 `StaticBody2D`。玩家和味真族均不能穿过。

### 灰盒导航

`KitchenNavigationGrid` 使用 `AStarGrid2D`：

- 根据 `kitchen_obstacle` 组中的实体设施矩形自动标记不可行走格。
- 路径每隔固定时间刷新，玩家绕设施移动后敌人会重新找路。
- 生成点必须处于可走格、离玩家达到安全距离，且能找到通向玩家的路径。
- 多只味真族额外使用局部轻量分离速度，避免完全重叠；不实现复杂群体寻路或协作包抄。

该方案是当前静态灰盒厨房的 Prototype 技术方案。正式地图可以替换为导航多边形，不应把当前网格尺寸视为长期关卡规则。

## 六、准备、预警与波次状态机

`PrototypeWaveManager.Phase`：

```text
PREPARATION
→ GLOBAL_WARNING
→ LOCAL_WARNING
→ SPAWNING
→ WAVE_ACTIVE
→ 下一批 LOCAL_WARNING / 最终 WAVE_COMPLETE
```

玩家生命归零会转为 `FAILED`。

### 准备阶段

玩家仍可取料、切割、腌制、开火、自动烹饪、摆盘、洗盘、洗粘锅和移动。倒计时不会影响任何厨房状态。

### 提前营业

- B：在准备期立即结束剩余时间，进入同一全局预警。
- 记录 `early_started` 和 `early_seconds`。
- 发出预留信号 `early_service_recorded(seconds_early)`。
- 不发放任何奖励。

金币、食材、经验、品质、倍率和正式奖励公式全部尚未确定。

### 全局与局部预警

- 全局预警文案：`味真族正在逼近！`，屏幕中央闪烁；期间玩家和厨房继续运行，尚不生成敌人。
- 每批生成前显示 `下一批将从 X 侧进入` 的局部预警。
- 当前有左、右、上、下共八个候选 Marker2D；每批随机选择一个通过距离、导航和占位检查的候选点。

### 分批与结束

当前临时配置为三批、每批两只，同批也以短间隔逐只进入；上一批没有全部复味时下一批可以开始。只有计划总数全部生成、场上战斗单位为零且复味离场计数达到计划总数时，才进入波次完成。

波次完成后：

- 不补充食材或盘子。
- 不清理物品栏、脏盘池、锅具或锅内内容。
- 不关闭灶火。
- B 可进入下一次相同准备测试；T 可重载完整场景。

正式波次间结算、成长选择和三选一奖励未实现。

## 八、操作与 Debug UI

- WASD：移动
- E：主要交互、开关火、按住加工或清洗
- F：物品拿取 / 投入
- R：炒锅搬运
- 鼠标滚轮或数字键 1—5：切换 Prototype 0.3.2 五格快捷栏
- Q：丢弃当前格
- Space：开始 / 确认摆盘
- M：待摆盘料理加入芥末
- 鼠标左键：料理攻击
- B：提前营业；波次完成时进入下一次相同准备测试
- T：重载当前测试场景

Debug UI 显示阶段、准备倒计时、提前营业与提前秒数、批次、场上数量、已生成 / 已复味数量、下一批时间、局部方向、玩家生命与当前食材库存。所有界面与按键均为 Prototype 占位。

## 十二、尚未确定与已知问题

尚未确定：

- 提前营业的正式奖励及计算方式。
- 正式波次奖励、掉落、经验与成长结构。
- 玩家正式无敌帧、受击保护、倒地和死亡流程。
- 正式批次、敌人数、准备时间、库存和盘子供应平衡。
- “复味”“调和”或其他正式战斗术语。

已知 Prototype 限制：

- 导航使用 32 像素静态网格，只适合当前灰盒设施；未测试动态障碍或大规模单位。
- 怪群分离是轻量局部力，极窄通道和较大规模怪群仍可能短暂拥堵。
- 局部预警只显示方向文字，不画出精确出生区域。
- 失败使用 T 重载，没有正式死亡演出或场内重开界面。
- Debug 右侧信息较密集，需要手动试玩确认 1280 × 720 下的阅读舒适度。
- 目前保留 0.2 的静止敌方 / 友方假人用于料理回归；它们不计入波次。

## 十三、下一步建议

先由开发者人工试玩并记录：

1. 三批压力是否真的迫使玩家离开战斗回锅，而不是只在一侧站桩。
2. 前摇与锁向挥击是否足够清楚、可躲又不显得无威胁。
3. 有限库存和 18 秒准备是否能形成“初始构筑”，而不是准备不足或提前做完整轮资源。
4. 味真族绕设施和怪群分离是否有卡角或抖动。
5. 料理焦糊是否来自可预判的忙乱，而不是缺少反馈。

在得到这轮人工试玩结论前，不增加第二敌人、掉落、经验、正式奖励或新料理。

## Prototype 0.3.1 节奏修订

首轮试玩确认原 18 秒准备、3.0 秒批次间隔、0.3 秒同批间隔以及 0.62/0.48 秒攻击前后摇不适合当前灰盒。0.3.1 已把它们分别调整为 32 秒、4.2 秒、0.55 秒和 0.36/0.28 秒。三批、每批两只、全局/局部预警、攻击锁向、攻击生效时间、攻击冷却、有限库存和提前营业规则均保持不变。

测试地图同步由 `910 × 664` 扩为 `1820 × 1328`，味真族继续使用相同 AStarGrid2D 绕障和轻量分离逻辑，但导航范围与八个出生点已迁移到新地图。厨房目前只是整体移动后的临时布局，正式地图形态尚未决定。完整旧值、新值、地图坐标和验收结果见 `Prototype_0_3_1_Pacing_and_Map_Adjustment.md`；本节修订优先于上文仍提及的“18 秒准备”旧试玩问题。
