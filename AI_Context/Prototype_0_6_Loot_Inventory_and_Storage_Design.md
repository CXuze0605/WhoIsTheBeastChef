# Prototype 0.6A：异形背包、真实仓储、牛肉多份加工与实体战利品

> 日期：2026-07-23
> 状态：Prototype 0.6A 实施依据；所有网格尺寸、形状、堆叠上限、初始数量和掉率均为临时试玩参数，不是永久最终数值。
> 前置：Prototype 0.5.1 试玩阻断修复已完成；D-068 至 D-071 继续有效。

## 1. 目标与范围

0.6A 只建立第一条可玩的局内资源闭环：

`有限初始食材 → 烹饪并战斗 → 味真族掉落实体资源 → 玩家靠近亲自拾取 → 快捷栏满后进入异形背包 → 带回异形食材柜 → 再取出用于后续烹饪`

本轮不一次完成完整肉鸽经济，不新增食材、料理、敌人或成长系统。所有物品继续由 `ItemData + CarryableItem` 表示，快捷栏、背包、柜子、工位和世界只是在不同位置持有同一个真实实例。

## 2. 四层容器职责

### 五格快捷栏

- 容量继续固定为 5，每格保存一个真实物品实例或一堆兼容物品。
- 当前选中格继续代表手持物，只有快捷栏物品可直接攻击、放入工位或执行厨房主要交互。
- 不使用异形占格，不改变已有选择、滚轮、数字键、耐久或手持接口含义。

### 玩家异形背包

- Prototype 临时尺寸 `6 × 6`。
- 保存真实物品实例，使用二维占格掩码、90 度旋转、越界 / 重叠检查和有限堆叠。
- 背包物品不能直接攻击或进入厨房主要操作，必须先移动到快捷栏。
- 跨波次与波间准备保留；正式新局、退出本局和返回大厅重置时清空。
- Tab 打开；Tab 或 ESC 关闭。界面打开时不暂停世界，但锁定玩家移动、攻击和厨房操作。

### 异形食材柜

- 正式本局 Prototype 临时尺寸 `10 × 8`；自由测试大厅临时尺寸 `20 × 20`。
- 与背包复用同一套网格、旋转、堆叠和原子移动规则。
- 保存真实物品实例，不再以六项整数作为权威存储。
- 正式新局按集中配置重新生成初始实例；跨波次保留；打开时不暂停世界。
- UI 同时显示五格快捷栏、玩家背包和柜子，并允许三者之间拖放。
- 网格内以物品图片和占格为主，不在狭小格子中强行显示完整长名称。完整名称、数量、旋转后的占格、品质和主要状态通过悬停信息栏 / Tooltip 展示；大件可使用不越界的紧凑名称条。
- 自由大厅使用同一个柜子节点和同一套真实实例 / 网格规则，但扩为可滚动 `20×20` 开发测试目录：覆盖当前 `ItemData.ItemType` 的全部 22 类物品，包含可直接战斗的完成料理；每种保留一个目录样本，取走后补回新的测试样本，从玩家角度视为不限量。
- 点击“开始营业”时，完整新局重置会把测试目录替换为下文的六类有限正式初始物资；测试目录物品不能带入正式本局，不能据此推导正式经济或掉率。

### 基础垃圾桶

- 0.6A 追加一个基础清理设备：玩家手持物品靠近后按 E，直接销毁当前选中快捷栏中的整个真实物品实例 / 兼容堆。
- 销毁不产生返还、掉落或统计奖励，不建立第二套物品转移系统。
- 本功能只解决测试和局内空间清理；腐败物转换、厨余价值、味真族强化、垃圾经济和确认交互仍属于后续设计。

### 未来冰箱

- 未来可复用同一网格容器，但不在 0.6A 创建节点、UI、保鲜倍率或升级逻辑。
- 冰箱、新鲜度和腐败属于 0.6B / 0.6C，不得为尚未确认的功能过度抽象当前实现。

## 3. 通用异形网格原则

每个网格记录：

- 网格宽高；
- 真实 `CarryableItem` 引用；
- 左上角格坐标；
- 当前旋转状态；
- 由集中目录提供的原始占格掩码；
- 容器变化信号。

通用逻辑必须支持合法性、越界、重叠、自动寻找、默认方向优先、旋转方向后备、添加、取出、同容器移动、合法交换、兼容堆叠和失败回滚。旋转状态保存在具体物品实例及其放置记录中，离开网格进入快捷栏后仍保留，下次放回网格继续使用。

移动以“先验证、再修改”为原则：失败时来源不变，不允许复制、丢失、删除或留下空引用。形状、堆叠上限和类型判断只使用集中数据及枚举，不使用显示名称。

## 4. 拾取路由

玩家亲自靠近世界物品并按既有拿取键后，按以下顺序尝试：

1. 合并到快捷栏已有兼容堆；
2. 放入快捷栏第一个可用格；
3. 合并到背包已有兼容堆；
4. 在背包默认方向自动寻找位置；
5. 默认方向失败后尝试旋转方向；
6. 两者都失败时世界实例保持原位，并提示“快捷栏和背包均没有足够空间”。

拾取不会全图吸取。一个实例在任意时刻只能属于世界、快捷栏、背包、柜子或工位之一。

## 6. Prototype 0.6A 临时堆叠目录

- 盐、辣椒段、腌肉料、芥末：最多 3。
- 食用油：最多 2。
- 焦炭：最多 3。
- 干净盘子、脏盘子：继续最多 4。
- 涮牛肉：继续最多 5。
- 整块牛肉、牛排、牛肉片包、腌牛肉片、料理和锅具：不堆叠。

堆叠兼容至少比较物品类型、加工状态、失败标签、组件、主动改造、品质、盘子状态、耐久 / 使用状态、剩余份数、毒伤 / 战斗状态和其他会改变料理结果的数据。0.6B 加入新鲜度时必须把新鲜度区间或具体规则加入兼容判断。

## 7. 初始柜存与掉落参数

正式新局的 Prototype 临时柜存：

- 整块牛肉 1；
- 腌肉料 1；
- 辣椒段 2；
- 食用油 2；
- 盐 1；
- 芥末 1。

一块整牛肉现在可产生三条牛排路线，因此不再沿用每类 4—12 份的 Debug 丰满库存。独立干净盘子堆继续使用既有集中配置。

普通味真族完成复味离场时只判定一次，临时基础掉落率 `35%`。当前权重目录为：食用油 24、盐 24、辣椒段 24、腌肉料 20、芥末 8；每只最多一份。重型味真族当前只作为掉落闭环验证者，完成复味时保证掉落一块整块生牛肉，不改名为精英。

掉落是世界中的真实 `CarryableItem`，在敌人完成复味的位置附近生成，不参与物理阻挡或导航，不短时自动消失，跨波次保留，并在正式本局结束、退出或刷新时清理。测试假人没有正式复味掉落入口。

放置后的涮牛肉必须显示可辨认的世界空间香气边界；显示和诱食判定必须共用 `PrototypeCombatConfig.shabu_aroma_radius`。反馈表现可以调整，但不得通过独立视觉半径误导玩家。

## 8. 牛肉三份加工

正式 0.6A 加工产量：

`1 块整块生牛肉（3×3） → 第一次完整切割 → 3 个互相独立的生牛排实例（每个 1×3）`

`任意 1 个生牛排 → 第二次完整切割 → 1 个生牛肉片包（1×1，remaining_portions = 5）`

切菜板在第一次切割完成后原子地消费原整块实例并建立三个独立牛排实例，暂存未取产出。每次只转移一块，使用“快捷栏优先、背包后备”的统一接收路由；两者都满时产出仍留在切菜板。三个产出未取完前禁止放入新原料。中断只重置当前 `HoldProgress`，不提前产生任何产出。

三块牛排分别继承原料需要延续的失败标签、组件、主动改造和品质等状态，但不是一个三数量堆。每块可独立煎制或继续切片。每个片包继续代表五片涮煮份数，因此一块整牛肉理论上可形成三份战斧、三份小炒原料或十五片涮肉。

## 9. 半成品“备菜构筑”的长期方向

异形空间使加工本身成为局内构筑选择：大型原料占据更多空间，切配后的半成品可能用更小形状提高携带效率，但也消耗实时操作时间并更早锁定路线。长期可以让某些加工改变新鲜度下降速度或保存条件，但加工只能继承已有失败 / 腐败状态，绝不能把已经腐败的物品恢复正常。

0.6A 只建立形状与实例基础，不实现新鲜度实际计时、保存倍率或腐败转换。

## 10. 本轮明确不做

- 新鲜度倒计时、腐败、垃圾加工 / 堆肥、厨余强化和浪费惩罚；基础“放入即销毁”垃圾桶已作为 0.6A 测试清理设备追加实现；
- 冰箱、局外冰箱升级或保鲜倍率；
- 新食材、新料理、新敌人、正式精英和 Boss；
- 波间奖励、经验、商店、稀有度和局外成长；
- 重量、移动惩罚、装备槽、嵌套容器、邻接加成、合成和背包战斗词条；
- 自动整理、一键排序、复杂搜索筛选；
- 多人或网络同步；
- 料理耐久与整体战斗数值调整；
- 正式美术、复杂音效、版本发布或 Git 操作。

## 11. 需要人工试玩确认

- `6×6` 背包、正式 `10×8` 柜子和大厅可滚动 `20×20` 测试目录在 1280×720 下的鼠标精度与可读性；
- 当前形状是否产生有意义空间取舍，锅具与盘子是否过度挤占；
- 初始 1 块整牛肉与少量调味是否足够启动第一波而不产生无限感；
- 35% 普通掉率和 24/24/24/20/8 权重是否让后续烹饪可持续；
- 重型保证整牛肉是否过强；
- 三牛排产出、逐块取走和切菜板剩余提示是否直观；
- 实体掉落在混战中的高亮、拾取反馈和地面堆积程度；
- Tab / ESC、拖放和 R 旋转是否顺手且不会与实时战斗输入冲突；
- 波间携带、柜存和地面掉落保留是否符合玩家预期。

## 12. 0.6A 实现落点（2026-07-23）

- `ItemStorageCatalog`：集中容器尺寸、物品占格和堆叠上限。
- `GridInventory`：保存 `CarryableItem` 放置记录，提供掩码、旋转、合法性、自动放置、原子移动 / 交换、堆叠和变化通知。
- `PrototypePlayer.backpack`：玩家 `6×6` 实际实例容器；世界拾取路由继续复用现有五格 `QuickInventory`。
- `IngredientCabinet.storage`：同一个实际实例容器在自由大厅为 `20×20`、正式本局为 `10×8`；旧 `get_stock()` 保留为兼容汇总查询，不再持有权威整数库存。
- `IngredientCabinetUI + InventoryGridView`：同一局部模态内显示五格、背包和柜子，支持鼠标拖放、R 旋转、失败回滚及 Tab / ESC。
- `CuttingBoard.pending_outputs`：暂存三个独立牛排，逐块走统一玩家接收路由。
- `PrototypeWaveManager`：在复味完成信号上执行一次性掉落判定，世界实体跨波次保留并走既有正式重置清理。
- `RunStats` / `RunSummaryUI`：记录并显示战利品生成数和拾取数。
- `ItemCatalog.duplicate_data()`：显式复制所有影响实例、加工、料理与战斗结果的运行时字段；不得以 Godot `Resource.duplicate()` 代替。

实现继续遵守本文件顶部声明：`6×6`、正式 `10×8`、大厅测试 `20×20`、形状、堆叠、初始数量和掉率仍是待人工试玩的临时参数。
