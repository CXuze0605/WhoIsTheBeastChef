# Prototype 0.4：牛肉料理分支与多波次测试

> 实现日期：2026-07-21  
> 性质：可运行灰盒增量；本文中的时间、伤害、距离、库存和敌人数均为 Prototype 临时参数，不是最终平衡。

## 一、本轮目标与边界

Prototype 0.4 在 0.3.2 的五格快捷栏、生命 HUD、扩大相机、自动烹饪和基础味真族上，补齐以下纵向测试：

```text
自由准备
→ 玩家主动开始营业
→ 三波连续战斗与波间准备
→ 小炒黄牛肉 / 战斧牛排 / 涮牛肉陷阱形成三种战斗形式
→ 普通与重型味真族混合验证
```

本轮没有加入新主食材、第三种敌人、Boss、正式奖励、商店、成长、联机、正式美术或正式音效。

## 二、已确认并实现的设计

### 1. 自由准备与开始营业

- 场景载入时立即完整初始化一局并进入 `FREE_PREPARATION`。
- 玩家立刻拥有移动、五格栏、取材、加工、自动烹饪、摆盘、洗盘、洗锅和放置陷阱权限。
- 自由准备没有倒计时，不生成味真族，也不记录提前营业奖励。
- 屏幕边缘只显示小型“开始营业”按钮，不使用阻塞世界操作的全屏遮罩。
- 点击后只把波次状态切换为全局来袭预警；玩家位置、生命、快捷栏、库存、盘子、陷阱、灶火、锅具内容和烹饪进度全部保留。
- 波间准备 `INTERMISSION` 有 20 秒 Prototype 倒计时；可提前开始下一波，只记录提前秒数，不发放未设计奖励。
- 失败或三波完成后“重新开始”才执行完整新局重置，并返回自由准备。

Prototype 0.3.2 的 `WAITING_TO_START → 开始游戏 → 倒计时准备` 是被本轮修正的旧实现，不再作为现行流程。

### 2. 通用灶位与锅具

地图配置两个通用灶位，以及炒锅、煎锅、汤锅各一口。每个灶位：

- 独立保存开火 / 关火状态；
- 一次只容纳一件实现 `CookwareItem` 接口的锅具；
- 不按料理显示名称判断烹饪；
- 把自动计时委托给实际锅具与锅内离散状态；
- 允许任意锅具在两个灶位之间移动，不绑定原灶位；
- 拿走锅具时清空当前未完成阶段进度，保留已完成状态、辣椒、盐、翻面和锅内内容。

单人场景初始为：灶位一放炒锅、灶位二放煎锅、锅具架保存汤锅，因此三口锅不能同时加热。粘锅锅具继续由玩家手持到同一水池持续清洗，清洗完成仍留在当前快捷栏格子中。

### 3. 战斧牛排制作与翻面

```text
整块生牛肉 → 生牛排
煎锅加油 → 放入灶位并开火 → 生牛排下锅
→ 第一面自动煎制 4.2 秒
→ 翻面窗口 1.4 秒
→ 第二面自动煎制 4.0 秒
→ 战斧牛排
```

- 翻面窗口使用煎锅上方局部环形提示，不暂停世界。
- 窗口内靠近煎锅按 E 正确翻面；窗口前操作无惩罚。
- 错过窗口会加入【翻面过晚】标签并自动翻面，流程不会永久卡死。
- 无油加热会产出焦炭并使煎锅粘锅。
- 完成后继续受热 3.0 秒获得【焦糊】，再持续 2.0 秒变为焦炭。
- 煎制期间可加入盐；盐不重置进度，且中断后保留。

### 4. 战斧牛排战斗与装盘资格

直接手持战斧牛排，单击左键产生一次近距离扇形挥砍：

- 基础伤害 42；基础耐久 4；攻击间隔 0.78 秒；
- 范围 112 像素；扇形 92 度；击退 130；`stagger_power = 100`；
- 同一挥砍用本次命中集合保证同一目标只受击一次，但可命中范围内多个目标；
- 每次挥砍消耗 1 耐久并把物品实例的 `has_been_used` 永久设为 `true`；
- 未装盘牛排耗尽后直接消失，不产生盘子或大骨头。

全局装盘资格由 `ItemData.is_eligible_for_plating()` 统一判断：

```text
current_durability == max_durability
has_been_used == false
```

它读取真实物品实例字段，而不是 UI 百分比。切格、放下和拾回都不会重置 `has_been_used`。当前允许装盘的待摆盘小炒黄牛肉和战斧牛排共用这一判断。

### 5. 盘装战斧牛排与大骨头

- 完整未使用牛排可消耗一个干净盘子进入现有摆盘 QTE。
- 零标签命中完美区为完美；零标签普通完成为正常；一标签为瑕疵；两标签以上为糟糕。
- 怪异料理即使命中完美区也不能达到完美。
- 非完美盘装牛排耗尽后，原格直接变为 1 个脏盘子。
- 完美盘装牛排耗尽后，同一个物品实例转换为“大骨头”，继续保留在原快捷栏格。
- 大骨头单击左键后沿瞄准方向飞行，伤害 30、速度 540、距离 520、命中半径 22、韧性 58；只命中第一个目标，不穿透、无范围伤害。
- 骨头命中或飞出范围后，来源实例再转换为脏盘子；不会同时生成骨头和盘子覆盖同一格。

### 6. 盐与芥末牛排

- 盐继续复用 `ActiveModifier.SALTED`，增加 2 点最大耐久，不改变伤害、范围、击退或攻速。
- 芥末只允许加入完整、未使用、已完成的战斧牛排；复用 `ActiveModifier.MUSTARD` 和既有毒伤控制器。
- 芥末牛排直接伤害乘 0.85，完整毒伤沿用 3 点 / 0.5 秒 / 2.0 秒及刷新持续时间的 Prototype 数据。
- 芥末不是失败标签；盐和芥末可同时存在。
- 芥末牛排不能成为完美，也不能生成大骨头。
- 每个牛排实例独立保存 `attack_count` 和 `next_sneeze_attack`。下一次喷嚏在随机第 2 或第 3 次挥砍后触发；触发挥砍正常结算，然后玩家进入 0.32 秒短僵直。
- 切换快捷栏不会重置计数；近战牛排不套用小炒芥末版本的持续瞄准晃动。

### 7. 生牛肉片五份与汤锅

生牛肉片实例默认保存 `remaining_portions = 5`：

- 下炒锅制作小炒黄牛肉时，整份实例一次消耗，仍代表五片共同成菜；
- 下汤锅时每次仅扣一份，5 → 4 → 3 → 2 → 1 → 0；
- 份数保存在物品实例中，切格、放下和拾回都不会重置。

汤锅流程：

```text
汤锅装水 → 通用灶位开火 → 水加热 2.4 秒至沸腾
→ 投入一片未腌制牛肉片 → 自动涮煮 1.0 秒
→ 涮牛肉 → 1.6 秒后【煮老】 → 再 1.2 秒后煮烂牛肉
```

- 水未沸腾时投入只给当前片加入【冷水下锅】；其他剩余份数不受影响。
- 当前成品未取走时不会处理下一片。
- 热水和灶火在取出成品后保留；当前不计算水量、蒸发或补水。
- 满物品栏时成品继续留在汤锅，不会覆盖或吞掉。
- 同失败标签、调味和品质的涮牛肉最多五片同格；状态不同的片不会强行合并。
- 涮牛肉当前不装盘、不使用耐久、不加盐或芥末、不产生脏盘。

### 8. 涮牛肉诱食陷阱

- 选中涮牛肉按 G，在玩家前方 74 像素的合法导航地面放置一片非正式餐垫占位。
- 不能放在墙体、设施或不可通行网格；放置成功消耗一份堆叠。
- 香气半径 310；一片同时只允许一个味真族锁定。
- 锁定者暂时放弃玩家并寻路至陷阱；到达后进入品尝状态，吃掉陷阱、受到一次复味伤害并短暂停顿，再恢复追击。
- 标准伤害 26、品尝 1.0 秒；一个失败标签乘 0.72，两个及以上乘 0.48。重型的品尝时间乘 1.25。
- 锁定者失效、完成复味、超距或超过 7 秒无法到达时释放锁定。
- 未锁定陷阱可由玩家 F 拾回一片；玩家和友方不会触发滑倒或自动食用。
- 陷阱跨波次和波间准备保留，只在完整新局重置时统一清理。
- 煮烂牛肉不能放置为正常诱食陷阱。

### 9. 重型味真族与韧性

重型味真族复用基础敌人的追击、攻击、诱食、毒伤和复味离场骨架，仅替换集中参数和占位表现：

| 参数 | Prototype 数值 |
|---|---:|
| 最大生命 | 165（普通 60 的 2.75 倍） |
| 移速 | 52 |
| 攻击距离 / 范围 / 宽度 | 72 / 98 / 112 |
| 前摇 / 生效 / 后摇 | 0.75 / 0.18 / 0.48 秒 |
| 攻击伤害 / 击退 | 22 / 88 |
| 攻击冷却 | 1.05 秒 |
| 韧性阈值 | 70 |
| 受击僵直 | 0.11 秒 |
| 击退倍率 | 0.38 |

所有料理攻击对普通和重型味真族的伤害倍率当前均为 1.0。普通公牛韧性 22，不能稳定打断重型砸击；战斧 100 可在前摇中打断；大型公牛 120 可造成明显反应。这里没有隐藏料理抗性或免疫。

### 10. 攻击形式与烹饪标签

标签保存在物品或状态效果数据中，不通过显示名称判断：

| 内容 | 攻击形式 | 烹饪方式 |
|---|---|---|
| 小炒黄牛肉 | `projectile` | `stir_fry` |
| 战斧牛排 | `melee` | `pan_fry` |
| 涮牛肉陷阱 | `trap` | `boil` |
| 芥末毒伤 | `damage_over_time` | 继承来源料理方式 |

本轮只提供数据标签和 `get_recipe_damage_multiplier()` 的 1.0 返回值，不实现物抗、魔抗、料理抗性、免疫或正式抗性 UI。

### 11. 三波状态机

现有单一 `PrototypeWaveManager` 调整为：

```text
FREE_PREPARATION
→ GLOBAL_WARNING → LOCAL_WARNING → SPAWNING / WAVE_ACTIVE
→ INTERMISSION
→ GLOBAL_WARNING → 第二波
→ INTERMISSION
→ GLOBAL_WARNING → 第三波
→ RUN_COMPLETE
```

临时配置：

| 波次 | 批次 | 每批普通 | 每批重型 | 总量 |
|---|---:|---:|---:|---:|
| 1 | 3 | 2 | 0 | 6 |
| 2 | 3 | 2 | 1 | 9 |
| 3 | 4 | 3 | 1 | 16 |

全局预警 2.0 秒、局部预警 0.8 秒、批次间隔 4.2 秒、同批生成间隔 0.55 秒。波间准备 20 秒。波次切换不重置生命、快捷栏、库存、锅具、灶火、盘子、烹饪或陷阱；第三波完成才进入 `RUN_COMPLETE`。

## 四、验证结果

- `prototype_0_4_smoke_test.gd`：PASS（9 / 9 组），覆盖自由准备、通用灶位、战斧与翻面、装盘 / 骨头 / 芥末、份数与汤锅、陷阱、重型韧性、三波和数据标签。
- 0.1、0.2、0.2.1、0.3、0.3.1、0.3.2 全部回归通过。
- Godot 4.6.2 编辑器资源扫描无 GDScript 解析或断开引用错误；主场景无界面启动无运行时脚本错误。

自动化确认状态转换、实例保存和主要碰撞 / 伤害合同，不替代开发者在 Godot 编辑器内对近战手感、翻面窗口、陷阱诱食可读性、重型威胁和三波节奏的人工试玩。

## 五、长期方向与尚未确定

长期方向（只记录，不实现）：

- 多人地图可选择性增加灶位与切菜位置，不默认复制整套厨房；食材柜、水池和摆盘位置可共享。
- 未来可以加入幅度较小的软抗性与弱点；加入前需要波次预览、视觉特征和清楚命中反馈，并尽量避免完全免疫。

尚未确定：

- 波间补充哪些食材、是否回血；
- 提前营业奖励类型与公式；
- 正式三波敌人数、战斧伤害、涮肉诱食范围和全部节奏参数；
- 多人灶位数量与正式厨房 / 锅具布局；
- 正式料理抗性倍率；
- 第三种敌人、Boss、油炸料理和新调味品。

## 六、已知 Prototype 限制

- 全部锅具、牛排、骨头、陷阱和重型味真族仍使用程序色块与文字占位。
- 通用灶位沿用历史脚本类名 `WokStation`，避免破坏既有场景和测试；后续稳定后可做纯命名迁移，但当前没有必要冒险重构。
- 翻面、近战、骨头、诱食和三波均通过自动化逻辑验收，但实际可读性与乐趣仍需人工试玩。
- 汤锅水不消耗；涮牛肉使用临时餐垫且不消耗正式盘子。
- 抗性只有标签与 1.0 接口，没有实际减伤。
- 波间没有正式补给、回血、奖励或结算。
